# 虚拟人物可定制化 · 可行性研究

> **状态：已立项为核心功能，P0 实施中**（架构落点见《AI虚拟角色系统技术架构设计文档 V1.2.md》§8.3）
> 2026-06-11 · 需求：人物不写死，要捏脸式定制、可对话调整、动作舞蹈可设定，并由 AI 构建专属虚拟人（参考 [lobe-vidol](https://github.com/lobehub/lobe-vidol)）
> 对应原需求文档 V1.0：§8.2.2 外观设定·模式B「自定义生成」、§8.3 表情与动作素材

## 一、结论

**可行。推荐「VRM 3D 主线 + 三层定制体系」，Live2D 降级为模板风格选项。**

- 浏览器侧 VRM 渲染 / 动作 / 口型生态成熟（lobe-vidol 同款技术栈）
- AI 文生 3D + 自动绑骨在 2026 已有商用 API（Meshy / Tripo），单角色 1~3 分钟异步生成
- Live2D 全自动生成（分层立绘→拆图→绑定）至今无可靠方案 —— 与 V1.0 文档标注的最高风险一致，
  「自由构造」诉求由 VRM 路线承接才能落地
- 现有后端（人设 / 记忆 / 语音通话 / Agent 建角）**零重构**，只换前端渲染层 + 新增资产生成管线

## 二、为什么是 VRM（对比结论）

| 路线 | 自由度 | 成熟度 | 动作/舞蹈 | 判断 |
| --- | --- | --- | --- | --- |
| Live2D 全自动生成 | 高 | ✗ 不成熟 | 每模型单独制作 | 放弃（纯人工 2~4 周/只） |
| Live2D 模板+换装调色 | 低 | ✓ | 模板自带 | 保留为 2D 风格选项 |
| **VRM 部件化捏脸** | 中高 | ✓ | **标准人形骨骼，动作全模型通用** | **主线 P1** |
| **AI 文生3D+自动绑骨** | 极高 | △ 有质量方差 | 绑 Mixamo 骨架直接吃动作库 | **主线 P2** |

VRM 的决定性优势：**标准人形骨骼 + 标准表情/口型 blendshape**，意味着动作、舞蹈、口型系统
只建一次，任何来源的角色（模板 / 捏脸 / AI 生成）都能直接套用 —— Live2D 做不到这一点。

## 三、三层定制体系（推荐架构）

```
L1 模板库      10~20 个 VRM 模板（商用授权），选完即用；Agent 按描述挑模板
L2 捏脸系统    部件化组装（发型/发色/瞳色/肤色/服装/配饰 + 调色），traits JSON 全量描述
               · AI 捏脸：LLM 把描述映射成 traits JSON（与现有 agent-draft 同构）
               · 对话调整：聊天指令 → traits diff → 实时重渲染（“头发换成银色”秒级生效）
L3 AI 全自动   网关文生图立绘（已验证）→ 用户确认 → Meshy/Tripo image-to-3D
               → 自动绑骨 → 转 VRM / 直接 GLB 入库（异步 1~3 分钟，质量门控+重roll）

动作/舞蹈      Mixamo 2500+ 动作经 vrm-mixamo-retarget 重定向 + VMD(MMD) 舞蹈播放
               情绪→动作映射复用已实现的 turn.start/end motion 事件协议
口型           VRM 标准 viseme(aa)，现有 RMS 直驱方案平移
```

## 四、技术拼图与证据（本次调研核实）

## 七、与现有工程的衔接

- 角色配置 `live2d` 字段升级为 `avatar`：`{type: live2d_template | vrm_template | vrm_traits | ai_generated, ...}`
- 前端 `Live2DStage` 抽象为 `AvatarStage` 接口（`setMouth / motion / setExpression / dance`），
  Live2D 与 VRM 实现并存，按角色配置选择
- motion 情绪事件、RMS 口型、打断逻辑与渲染器无关，直接复用
- P0 第一步建议：先用 1 个 CC0 VRM 模型 + 2 个 Mixamo 动作 + 1 支 VMD 舞蹈做端到端 PoC（约 1~2 天）
